# Localisation

All player-facing text goes through `t(key, vars)` from `src/i18n/index.ts`. English (`src/i18n/en.json`) is the source of truth; every other locale is a machine-drafted first pass that falls back to English key by key.

## Locales

| Code      | Language             | Status                       |
| --------- | -------------------- | ---------------------------- |
| `en`      | English              | source                       |
| `es`      | Spanish              | draft, needs a native review |
| `pt-BR`   | Portuguese (Brazil)  | draft                        |
| `de`      | German               | draft                        |
| `fr`      | French               | draft                        |
| `it`      | Italian              | draft                        |
| `ja`      | Japanese             | draft                        |
| `ko`      | Korean               | draft                        |
| `zh-Hans` | Chinese (Simplified) | draft                        |
| `ar`      | Arabic               | draft, RTL, six plural forms |
| `tr`      | Turkish              | draft                        |

The `dev.*` keys (developer panel) exist only in English on purpose.

## Rules

- Keys are namespaced: `hud.`, `toast.`, `mech.`, `fail.`, `win.`, `ad.`, `shop.`, `product.`, `offer.`, `daily.`, `map.`, `decor.`, `settings.`, `time.`, `pause.`, `confirm.`, `tutorial.`, `dev.`.
- Interpolation uses `{name}`. Every placeholder in English must survive in every locale; the test `tests/i18n.test.ts` checks it.
- Plurals are objects keyed by CLDR category (`zero`, `one`, `two`, `few`, `many`, `other`); `other` is required. The category comes from `Intl.PluralRules` for the active locale, with `n` taken from `vars.n` (or `vars.count`).
- Data tables (products, decor, colours, mechanics) keep their ids in code and get their names from `product.<id>.name`, `decor.<id>.name`, `colour.<name>`, `mech.<kind>.title`.
- `tests/strings.test.ts` scans the UI code for quoted English prose outside `t()`. Add `// i18n-ignore` on a line that legitimately holds prose (there are none today).

## Choosing a language

Settings > Game > Language cycles through Automatic and the eleven locales. Automatic maps `navigator.language` with `matchLocale()`: any `pt-*` to `pt-BR`, any `zh-*` to `zh-Hans`, otherwise the two-letter base or English. The choice is saved in `S.lang` (empty means automatic).

## Right-to-left

Arabic sets `document.documentElement.dir = "rtl"` and the canvas text direction, so Arabic runs shape correctly and mixed numbers sit right. The layout itself stays left-to-right: the belt, the grid and the buttons keep their places, which is the norm for mobile puzzle games and keeps the tutorial pointing at the same spots. The smoke test switches to Arabic, confirms `dir` and that translated strings contain Arabic script, and screenshots the Settings screen.

## Fonts

Baloo 2 covers Latin only. Japanese, Korean, Chinese and Arabic fall through the font stack to the system font (Trebuchet MS, then `system-ui`), which is what you see in the screenshots. A bundled CJK/Arabic face is a Phase 5 store-polish item.

## Adding a string

1. Add the key to `en.json`.
2. Add it to every other locale (or accept the English fallback for a developer-only key under `dev.`).
3. Use `t('the.key')` in code. Run `npm test`.
